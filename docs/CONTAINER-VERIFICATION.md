# 컨테이너 검증 결과

검증일: 2026-10-20. Docker Engine 29.8.2, MariaDB 11.4.13, Java 17, Spring Boot 4.0.6, Caddy를 사용했습니다.

| 항목 | 확인 결과 |
| --- | --- |
| 이미지 빌드 및 시작 | 백엔드·웹 이미지 빌드 성공, DB healthy |
| 운영 DB 스키마 | Flyway V1 적용 및 Hibernate validate 통과 |
| MariaDB 저장 | 스냅샷 JSON을 SQL로 읽어 전체 카드 슈 순서를 포함한 상태 비교 |
| 백엔드 강제 종료 | SIGKILL 후 재실행, 동일 라운드·카드·베팅·잔액·세션 복원 |
| 게임 재개 | 복구 시 일시정지, resume 요청 후 정상 정산 |
| 정산 이후 재시작 | 백엔드 및 MariaDB 재시작 후 잔액 유지, 정산 내역 중복 없음 |
| 다중 사용자 | 실제 HTTP/STOMP로 두 사용자 3라운드 및 계정 잔액 검증 |
| 접근 제어 | 인증 없는 연결, 다른 방 연결·구독 거절 |
| 토큰 | 동시 refresh 요청 중 하나만 성공, 회전·로그아웃 후 기존 access 거절 |
| 요청 제한 | 인증 빈도 제한 및 16KiB 초과 요청 차단 |
| 단일 쓰기 서버 | 두 번째 백엔드가 advisory lock을 얻지 못하고 종료 |
| 컨테이너 권한 | 백엔드 UID/GID 10001, 루트 파일시스템 읽기 전용 |
| 내구성 설정 | `innodb_flush_log_at_trx_commit=1` 확인 |
| 프록시 | HTTP health 200, CSP 헤더 확인, loopback 포트만 공개 |

실행 명령과 종료·백업 방법은 [배포 안내](DEPLOYMENT.md)에 있습니다. 검증용 프로젝트 이름은 `blackjack-verify`, 접속 주소는 `http://localhost:18081`입니다. 기존 개발 서버의 H2 DB와 분리된 MariaDB volume을 사용합니다.

초기에는 Docker Desktop 화면 프로세스만 남고 엔진이 중지되어 있어 앱을 재시작했습니다. 이후 호스트 드라이브 저장 공간 소진으로 Docker 파일시스템이 읽기 전용으로 전환되는 문제를 확인했습니다. 공간 확보, 종료된 디스크 백업 및 해시 검증, 엔진 재시작, 손상된 빌드 캐시 교체 후 위 검증을 다시 통과했습니다. 실행 스크립트에 호스트 저장 공간 사전 검사를 추가했습니다.

이 결과는 로컬 컨테이너와 프로세스 재시작에 대한 검증입니다. 공개 도메인 DNS·TLS 인증서 발급, 장시간 부하, 디스크 자체 손상 시 DB 복원은 별도 검증 대상입니다.
